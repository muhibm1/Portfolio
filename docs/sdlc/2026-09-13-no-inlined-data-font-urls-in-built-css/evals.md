failure, and adversarial cases that exercise a real surface of this change: the `neverInlineFonts`

## 9. Gaps found in the spec's contract

Reported for the spec architect, not fixed here, per this role's scope. All three gaps from the
revision-0 version of this file were closed by spec revision 1's [Response to
audit](./spec.md#response-to-audit). Gap 2's revision-1 answer is itself superseded in spec revision
2, recorded below.

1. **Closed.** "R100's live smoke check is narrower than R97's build-time check." Closed by decision
   D5: R100 now applies R97's full rule, in bash, to the served stylesheets (spec Interfaces (c)).
   Proven by R98 case 4 (FL31) at build time and R104 case F3 (FL41) live; AD19 reflects the closure.
2. **Closed, superseded in spec revision 2.** "The spec does not say whether `neverInlineFonts` must
   be exported." Revision 1 decided: not exported, tested through `vite.config.js`'s default export.
   The spec's own re-audit (audit M5) found that approach does not work: a jsdom test importing
   `vite.config.js` fails at load, on esbuild's `TextEncoder` invariant (confirmed by the conductor),
   so revision 1's `src/viteConfig.test.js` never ran. Revision 2 withdraws that answer and moves the
   function into its own dependency-free module, `scripts/never-inline-fonts.mjs`, exporting
   `neverInlineFonts` by name (R93, ADR 0001). GC95, EG24, and EG25 are updated to import and call it
   directly, and GC103 lists the new module and its test file in place of `src/viteConfig.test.js`.
3. **Closed.** "The regex contract for `url(data:font` does not address a comment." Decided: the
   pattern is not widened; the prefix rule independently catches the case (R98 case 4, spec
   Interfaces (b)). Proven by FL31's third example. AD20 reflects the closure.

No case in this file documents an open gap as of this update. If a future spec revision reopens any
of the three, this section is the place to record it again.
